# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is
**E-Magang Kota Madiun** ("magange") — an internship-application portal for the Madiun city government. Three roles (app/Enums/UserRole.php): **Mahasiswa** (applicant), **Admin Verifikator** (screens incoming applications), **Admin OPD** (the placement agency that approves/rejects and manages active interns). UI, code comments, and domain terms are in **Indonesian** — match that language when editing.

The application lifecycle is the enum app/Enums/ApplicationStatus.php: pending_verifikator → forwarded_opd → **waiting_tte** → approved → ongoing → completion_submitted → **needs_certificate** → completed (with rejected as a terminal branch). The two bolded statuses are the **TTE (tanda tangan elektronik)** flow — see that section below; `completed` means "period ended AND a signed certificate was issued", not just "period ended". InternshipApplication is the central model; supporting models cover OPDs, OPD signers + letter templates, OTP tokens, status-log audit trail, documents, daily attendance (presensi), final reports, satisfaction surveys, FAQs, and form rate-limiting.

## Stack
Laravel 13 (PHP 8.3+) + Inertia v3 + React 19 + TypeScript, built on the laravel/react-starter-kit. Vite for bundling, Tailwind v4 for styling, shadcn/ui ("new-york" style) for components, Pest v4 for tests, PostgreSQL for the database. Authentication is Laravel Fortify plus a custom email-OTP login flow for mahasiswa (WhatsApp numbers are contact data only — OTP delivery is email, via SendOtpEmailJob). Mail goes out through railsware/mailtrap-php; PDFs through barryvdh/laravel-dompdf.

Framework conventions (PHP style, Inertia v3 patterns, Pint, Pest, Wayfinder, Boost MCP tooling) live in **AGENTS.md** — read it before non-trivial changes; it is the authority for those, so this file doesn't restate them. Domain skills (Inertia/React, Wayfinder, Fortify, Pest, Tailwind, Laravel best-practices) live in .cursor/skills/** (registered in boost.json); AGENTS.md requires activating the relevant skill when working in that domain. This file covers what's specific to *this* repo.

## First run / environment
There is still **no `.env.example`**, so `composer setup` (and Composer's `post-root-package-install`) fails at its `copy('.env.example', '.env')` step — write `.env` by hand instead. A **`README.md` does now exist** (added 2026-08-06) but it is **not authoritative and contradicts the code on three points**: it credits role handling to *Spatie Laravel Permission* (not installed — see the `UserRole` enum + `EnsureUserRole` under Architecture), states PHP >= 8.2 (composer requires `^8.3`), and says the acceptance letter is generated and sent automatically on approval (the TTE flow deliberately does **not** auto-send). Treat this file and AGENTS.md as the source of truth, not the README. Keys the app actually reads: `APP_KEY`, `APP_URL`, `DB_*` (pgsql), `SESSION_DRIVER=database`, `QUEUE_CONNECTION`, `FILESYSTEM_DISK=local`, `MAIL_*`, `RECAPTCHA_SITE_KEY`/`RECAPTCHA_SECRET_KEY` (optional), `APP_SCHEDULE_TIMEZONE`.
- **`APP_URL` must include the scheme.** A scheme-less value silently corrupts every generated URL (phpunit.xml pins its own `APP_URL` for exactly this reason). Local dev often repoints it at an ngrok host — `ngrok.bat` in the repo root is a personal helper for that: it is **untracked, contains a live authtoken, and must never be committed**. Since 2026-07-31 the **email logo no longer depends on `APP_URL`**: resources/views/mail/partials/header.blade.php embeds `public_path('images/Lambang_Kota_Madiun.png')` inline via `$message->embed()` (CID), so mail renders even when the local/ngrok host is down; the `config('app.url')/images/…` URL survives only as the fallback when that PNG is missing.
- **`APP_TIMEZONE` stays UTC** (changing it would reinterpret every timestamp already in the DB); scheduling uses `APP_SCHEDULE_TIMEZONE` (default `Asia/Jakarta`) instead.
- **The test suite needs a real PostgreSQL database named `magang_test`.** phpunit.xml pins `DB_CONNECTION=pgsql` + `DB_DATABASE=magang_test` with no SQLite fallback, so `php artisan test` (hence `composer test`/`ci:check`) dies without it. Run the suite on PostgreSQL, not SQLite — see the constraint bug in the TTE section for why that matters.
- **Wayfinder output is gitignored** (resources/js/{actions,routes,wayfinder}), so on a fresh clone `npm run types:check` and `npm run build` fail until `php artisan wayfinder:generate --with-form` has run. Only `npm run dev` runs it for you.
- **Queue behaviour depends on your `.env`.** With `QUEUE_CONNECTION=database` the worker from `composer dev` is required or dispatched Jobs/Mail never process; with `sync` they run inline and a missing worker won't show up until production. (The current dev `.env` sets the key twice — last wins.)

## Business rules & invariants (CRUCIAL — do not "improve" these)
1. **Authentication split & session security.**
   - **Mahasiswa:** no password. Email → OTP → login; OTP TTL **5 minutes** (OtpService).
   - **Admin (Verifikator & OPD):** conventional username + password at `/admin/login`. Never OTP for admins.
   - **Single session:** one browser must not hold two accounts at once — 403 Forbidden if detected, plus every other session for that user is invalidated on login.
   - **Progressive OTP lockout (Fibonacci):** 3 wrong OTPs → active tokens invalidated (user must resend) and resend blocked for a cooldown escalating per lockout level (1, 1, 2, 3, 5, 8… minutes). Resets on successful login or after 24h idle. app/Services/OtpLockoutService.php + otp_lockouts table, wired into Auth\OtpLoginController (both send and verify are blocked while locked; the page shows a live countdown from the `lockoutSeconds` flash prop).
   - **Forced password change:** auto-generated admin accounts carry `must_change_password`; middleware `password.changed` (EnsureMustChangePassword) pins them to GET/POST admin/password-baru (Auth\ForcePasswordController) before any dashboard opens. Credentials are shown once via the `generatedCredentials` flash prop. `last_login_at` is recorded on both login paths.
2. **Role-based form & UI constraints.**
   - **Public form (welcome.tsx `#daftar`):** `Jurusan` (optional) + `Keahlian` (textarea) sit right above `alamat_lengkap` → `major` / `skills` columns. `nis` (NIM) is alphanumeric, max 15. The **required** supervisor WhatsApp is `campus_supervisor_whatsapp`. `guardian_name`/`guardian_whatsapp` were **dropped** (migration 2026_07_19_000100) — do not reintroduce them; `person_in_charge` is a different column (OPD placement) and is unaffected.
   - **Admin Verifikator** sees Jurusan + Keahlian when reviewing and may fill **only** "Catatan Khusus Admin Verifikator". They cannot assign Divisi, Pembimbing Lapangan, or Penanggung Jawab.
   - **Admin OPD** approving via "Putuskan" → ACC **must** fill `Divisi/Bidang`, `Pembimbing Lapangan`, and `Penanggung Jawab`, with the alert below the form: *"Notif ini akan dikirim ke peserta magang. Peserta akan datang berkunjung ke kantor setelah diterima pengajuan ini"*.
   - **Verifikator owns OPD CRUD** at verifikator/opd/* (Verifikator\OpdController, mirroring FaqController): deletion refused while `quota_used > 0`, quota can't drop below `quota_used`. The older "Kelola Kuota OPD" page (verifikator/kuota + PATCH kuota/{opd}) is **kept for compatibility** — Admin OPD still edits its own quota there.
   - **OPD dashboard filter order** is `Perlu Keputusan` (yellow) · `Disetujui` · `Sedang Magang` · `Selesai Magang` · `Ditolak` · `Semua`, satisfied across **two tiers** (read left→right, then top→bottom) since the 2026-07-30 redesign: `ACTION_FILTERS` renders Perlu Keputusan / Menunggu TTE / Perlu Sertifikat as "Butuh tindakan" cards, `STATUS_FILTERS` renders the rest as chips on the table toolbar. One control surface split by role — **don't merge them back into one row and don't re-add a separate stat-card strip**; that duplication (two controls writing the same `filter` state with different membership) was the bug the redesign removed. The "Kelola OPD" settings card stays a **`Collapsible`, default closed, below the table** — settings must not push the work list off-screen. Since 2026-07-31 it holds **kuota + tag + the three placement masters** (Bidang/Penempatan, Pembimbing Lapangan, Penanggung Jawab — `opd_placement_options`, name only, CRUD in the Kelola FAQ style); **Data Surat and Penandatangan moved out to the Kelola Surat page** — don't move them back.
   - **Placement masters are suggestions, not a whitelist.** The three approve-form fields render an `<input list=…>` + `<datalist>`, so an admin may pick a registered name **or** type a new one; the payload stays a plain string on `internship_applications`. Don't convert them to foreign keys.
   - **`Verifikator\DashboardController::recentApplications` intentionally has no limit** — the stat cards and filter chips are computed frontend-side from that collection. Don't re-add a limit without moving those counts into separate queries.
3. **Status automation (cron).** Daily at `01:00` **WIB** (routes/console.php → `magang:transition-statuses`). Because `config('app.timezone')` stays UTC, the schedule pins `config('app.schedule_timezone')` and the command must read "today" in that same zone (`Date::now(config('app.schedule_timezone'))`) — 01:00 WIB is 18:00 UTC the *previous* day, so reading UTC makes every transition a day late (tests/Feature/Feature/Penyelesaian/TransitionTimezoneTest.php).
   - `approved` + `start_date <= today` → `ongoing`.
   - `ongoing` + `end_date <= today` → `needs_certificate` (legacy applications without a signer snapshot still go straight to `completed`).
   - `<=`, not `==`, so a missed run catches up.
   - **Period rules:** `duration_months` is never trusted from the client — StoreApplicationRequest recomputes it as `round(days / 30.4375)`, min 1. The range is capped at 12 months via `end_date` → `before_or_equal:{start + 1 year}` (rejected, not clamped); welcome.tsx mirrors that through the `DatePicker` `max` prop + `maxTanggalSelesai()`. `SubmissionService::resubmit()` shifts a past period forward to start today, preserving its length in days, and notes the shift in the status log.
4. **Four completion actors.** `completed` can be triggered by 1) the cron, 2) the user (final report + completion checkbox), 3) Admin Verifikator (manual button), 4) Admin OPD (manual button). **Admin OPD** reviews the final report and uploads the certificate from the "Kelola Peserta" detail dialog (moved from Verifikator). The satisfaction survey gates the certificate download — but **only on the legacy path**; see the known discrepancy in the TTE section before touching either side.
5. **Emails.** Contract: resources/js/pages/format_email.txt (**deleted in the working tree but still in HEAD** — read it with `git show HEAD:resources/js/pages/format_email.txt`) — large blue header "magang kota Madiun" + Lambang Kota Madiun logo via resources/views/mail/partials/header.blade.php, status badge ("disetujui"/"ditolak"), and rejection signed "Hormat kami, admin verifikator/OPD". Approval mail includes applicant + placement details (Divisi, Pembimbing, Penanggung Jawab), a PDF attachment, and: *"Anda diharapkan hadir di kantor OPD terkait dengan menemui perwakilan dari bidang [Nama Bidang]... dipandu oleh [Nama Pembimbing]"*. Laravel's vendor mail views **are published and modified** (resources/views/vendor/mail/html/* + themes/default.css) — theme changes go there, never in vendor/.
6. **Other cross-cutting rules.**
   - **Nomor SK:** `SkNumberService` (sk_counters table, `lockForUpdate`, format `503.11/N/401.106/TAHUN`) is called idempotently from SubmissionService::approve (`sk_number`/`sk_issued_at`, set once) and Opd\ReportController::generateCompletionLetter (`final_reports.completion_sk_*`). Start number: PATCH verifikator/sk-counter (still Verifikator's).
   - **Presensi is a daily absen:** presensi_logs has `status` (hadir/izin/sakit), `activity_date` auto-set to today (never client input), and **unique(user_id, activity_date)** → 1×/day (duplicate → "Anda sudah presensi hari ini." on the status field). Clock time is read from `created_at`; legacy `start_time`/`end_time` stay nullable. Dokumentasi Foto is **1–3 images, 2MB each** (StorePresensiRequest). Attachments (private disk) are openable by the owner **or** an admin (route presensi/{log}/lampiran/{attachment}, three roles). Index sends `entries` + `hasToday`; Word/Excel export is client-side.
   - **One active internship per email (implemented 2026-08-06, commit `1e7d637`).** A person may hold only **one** live application, and someone who has already finished an internship may **never register again**. The live statuses are the seven listed by `ApplicationStatus::activeStatuses()` (pending_verifikator → needs_certificate); `completed` history blocks separately. **`rejected` deliberately does NOT block** — otherwise "Ajukan Ulang" and honest re-registration after a refusal would die. Enforced in **two layers on purpose**, because the registration endpoint is public: `StoreApplicationRequest::after()` (attaches the message to the `email` field so the form shows it) and again in `SubmissionService::submit()` + `::resubmit()` (`DomainException`). Covered by tests/Feature/Feature/Mahasiswa/SatuMagangAktifTest.php. Don't "simplify" this to one layer. **Layer 2 only reaches the user because `Mahasiswa\ApplicationController::store()` catches the `DomainException`** and turns it into an `email` validation error (added 2026-08-06) — without that catch the second of two concurrent submissions from the same email is an uncaught **500**, since both pass the FormRequest before either row exists. Any new controller calling a service transition needs the same catch; `resubmit()` in that file is the reference. The frontend side is finished too: welcome.tsx renders `errors.email` under the field and scrolls to it (`post()` uses `preserveScroll`, so without that the message is off-screen), and mahasiswa/pengajuan.tsx shows `errors.resubmit` in place instead of bouncing to `/#daftar`.
   - **Ajukan Ulang:** SubmissionService::resubmit guards rejected + ownership, issues a new ticket, replicates form fields, physically copies files to applications/resubmit/{tiket}/, clears `opd_id`, logs "Diajukan ulang dari {tiket-lama}". It additionally refuses when the owner has another active application or any completed one (same rule as above).
   - **reCAPTCHA v3:** App\Rules\Recaptcha checks score (`services.recaptcha.min_score`, default 0.5) + optional action, on StoreApplicationRequest (`daftar`), SendOtpRequest (`otp_send`), and Fortify admin login (`admin_login`). Keys only via config/services.php. Skipped entirely when no secret is set, so dev/test without keys still passes.
   - **XSS sanitation:** global `SanitizeInput` middleware strips `<script>`, `on*=` attributes, and `javascript:` URIs; passwords are exempt; hyphens and ordinary punctuation survive. **Don't add further escaping at render time** — React/Blade already escape.
   - **OPD competency tags** come from `opds.description` split on commas (landing page reads it; the static `tagsByName` dictionary in welcome.tsx is only a fallback when description is empty). Edited via PATCH opd-tag/{opd} (OpdQuotaController@updateDescription) + the inline `TagEditor` on opd/dashboard.tsx.

## TTE flow — signed acceptance letter & certificate
Surat Penerimaan and Sertifikat are **not auto-emailed**. Both are signed manually outside the system, uploaded, and only then emailed. Contract: prompt/QUEUE/2026-07-29-batch.md.
- Approve with a signer → `waiting_tte` (draft PDF generated, **no email**); upload the signed letter → `approved`/`ongoing` + SendSignedAcceptanceLetterJob. End of period (cron) → `needs_certificate`; upload the signed certificate → `completed` + SendSignedCertificateJob.
- **Approving requires a signer AND a complete letterhead** (`ApproveApplicationRequest`: `signer_id` unconditionally `required` + scoped `exists`, plus an `after()` hook that errors on `signer_id` when the OPD has no signer and on `letterhead` when any of `letterhead_address/phone/email` is blank). This closed the bug where `signer_id` was only `requiredIf` the OPD already had a signer: an OPD that hadn't registered one yet could approve, the application went straight to `approved` with the old auto-email, and never appeared in Menunggu TTE. The frontend mirrors the same gate through `resources/js/lib/opd-readiness.ts` (`opdReadiness()`), used by **both** `opd/keputusan.tsx` and the duplicated approve form in `opd/dashboard.tsx` `DecisionDialog` — change both or the rule forks.
- **Legacy applications without a signer snapshot (`acceptance_signer_name === null`) deliberately keep the old flow** (straight to `approved`/`completed` + automatic email) so the pre-feature archive stays intact. Don't delete that branch in SubmissionService::approve/complete or TransitionApplicationStatuses. Such records can be pulled back into the TTE flow one at a time via `SubmissionService::reissueForTte()` (POST opd/pengajuan/{application}/tarik-tte, button in the Kelola Peserta detail dialog) — it writes the snapshot, moves the status to `waiting_tte` and regenerates the draft, but deliberately **does not** touch `quota_used` or reissue `sk_number`.
- **The `status` column is a plain VARCHAR, not an enum.** Migration 2026_07_29_120827 widened the type, but PostgreSQL kept the CHECK constraint that `$table->enum()` had created — it blocked every TTE transition (SQLSTATE 23514) until migration 2026_07_30_000100 dropped it. Valid statuses are now enforced only by the application-level enum cast, so **a new status needs no migration**. (Lesson: `->change()` on SQLite rebuilds the table, which hid this class of bug — run the suite on PostgreSQL.)
- **Models/tables:** `OpdSigner` (opd_signers — per-OPD signer master, one `is_primary`) and `OpdLetterTemplate` (opd_letter_templates — body per OPD per `type`: TYPE_ACCEPTANCE / TYPE_CERTIFICATE). Letterhead columns on opds: `letterhead_address/phone/email`. **Signer snapshots** live on internship_applications (`acceptance_signer_id/name/title/nip`) and certificates (`signer_*`), set **once** (`ensureAcceptanceSnapshot`/`ensureCertificateSnapshot` early-return) so old documents keep naming whoever actually signed. Paths: `acceptance_draft_path` / `acceptance_signed_path`, `certificates.draft_path` / `certificates.file_path`.
- **app/Services/LetterDocumentService.php** is the single source for draft-PDF generation and placeholder substitution; `PLACEHOLDERS` / `REQUIRED_PLACEHOLDERS` (per document type) are its contract, and a removed required placeholder is rejected in LetterController@updateTemplate. The letterhead is resources/views/pdf/partials/letterhead.blade.php — agency name/address/phone/email are per-OPD, the **Lambang Kota Madiun logo is static for all OPDs** and skipped when GD is absent so generation never fails. Views: pdf/{acceptance_letter,completion_letter,certificate}.blade.php.
- **Routes (all `role:admin_opd`, each action ownership-guarded 403):** `Opd\TteController` (GET opd/menunggu-tte, GET opd/perlu-sertifikat, draft + upload for both documents), `Opd\LetterController` (GET opd/surat, PATCH opd/data-surat, POST/PUT/DELETE opd/penandatangan[/{signer}], PUT opd/surat/template, GET opd/surat/arsip/{application}/penerimaan + /{certificate}/sertifikat), and `Opd\PlacementOptionController` (POST/PUT/DELETE opd/penempatan[/{option}]). These endpoints **never take an OPD id** — always the logged-in admin's OPD.
- **Kelola Surat (`opd/surat.tsx`) is three inline tabs**, not three pages: *Data & Penandatangan* (letterhead read/edit + signer CRUD in the Kelola FAQ style — list, inline edit, "Jadikan Utama", two-step delete), *Template Surat* (unchanged placeholder editor), *Arsip Dokumen TTE* (signed letters + certificates, server-side `?cari=` matching `sk_number` first, then ticket/participant name). Deleting a signer is safe: the FKs are `nullOnDelete` and the name/title/NIP live on snapshot columns.
- **KNOWN DISCREPANCY — the TTE certificate path skips the mandatory survey.** `CertificateService` (legacy) creates certificates with `is_download_locked = true` and only clears it after the satisfaction survey (`:32` / `:61`). The TTE path does not: `Opd\TteController::generateCertificateDraft` (`:78`) and `::uploadCertificate` (`:112`) both write `is_download_locked => false`, so a participant finishing through TTE can download without ever filling the survey. This contradicts the invariant in rule 4 and is **unresolved, not intentional** — it is decision #7 in resources/js/pages/plan_revisi_akhir.md. Don't quietly align one side to the other; the two paths disagree and which one wins is a product call.
- **Kuota is unaffected:** `quota_used` increments on approve and is never decremented, so the shifted meaning of `completed` doesn't change quota behaviour.
- Sidebar OPD (magang-layout.tsx `opdNav`): Dasbor · Perlu Keputusan · Menunggu TTE · Perlu Sertifikat · Kelola Peserta · Kelola Surat · Bantuan · Lacak. "Kelola OPD" is a dashboard card, not a sidebar item. The signer dropdown also appears in the approve form on opd/keputusan.tsx.
- Tests: tests/Feature/Feature/Opd/TteFlowTest.php — both document flows, Data Surat, signer CRUD + primary/Plt handover, the approve gate (no signer / no letterhead → 422, quota untouched, no job queued), `reissueForTte`, the signed-document archive + SK search, templates + required placeholders, placeholder substitution (read via `View::composer` because DomPDF compresses the PDF), dynamic letterhead + logo, snapshot durability, cron transition, 403/422 guards, and prop completeness for all three TTE pages. Placement masters: tests/Feature/Feature/Opd/PlacementOptionTest.php.

## Architecture
**Inertia, not an API.** Controllers return `Inertia::render('page-name', [...props])`. React pages in resources/js/pages/ receive those props directly. There is no REST/JSON layer — server and client are coupled through Inertia.

**Layouts: starter-kit pages are global, role dashboards self-wrap.** resources/js/app.tsx's `layout()` maps by page name: auth/* → AuthLayout, settings/* → [AppLayout, SettingsLayout], everything else → AppLayout. **But** role dashboards and branded public pages (mahasiswa/*, verifikator/*, opd/*, auth/otp-login, auth/force-password, lacak, bantuan, pengaturan, welcome) return null there and import **MagangLayout** (resources/js/layouts/magang-layout.tsx) themselves — check app.tsx before adding a page. MagangLayout is the branded (Pemkot Madiun blue #106feb) shell; it takes `navItems` and exports the per-role arrays `mahasiswaNav`, `verifikatorNav`, `opdNav`.

**Every self-wrapping MagangLayout page MUST receive a `user` prop** (`'user' => new MagangUserResource($request->user())`) — the shell reads `user.role`/`user.name` unconditionally and does **not** fall back to the `auth.user` shared prop. Forgetting it is a silent failure: the server returns **200**, React throws while rendering and unmounts the tree, so you get a blank white screen with nothing in the Laravel log. That bit `/opd/surat` (fixed 2026-07-30). When adding such a page, assert `has('user.name')` in its test.

**Pages are large and self-contained.** welcome.tsx is ~2720 lines; opd/dashboard.tsx ~1950; opd/peserta.tsx ~1370; verifikator/dashboard.tsx ~1010. opd/peserta.tsx's detail dialog is now **tabbed** (`Data Detail` / `Jejak` / presensi) rather than one long scroll — the tab list is an inline constant in that file. Sub-components, filter constants (`ACTION_FILTERS`/`STATUS_FILTERS`), dialogs and editors (`TagEditor`, detail dialogs) are declared inline at the top of the page file, not in components/ — edit them in place and don't split a page into modules as a side quest. Consequences worth knowing: resources/js/components/landing/* (hero, registration-form, faq-section, opd-directory, navbar, …) is **dead code** imported by nobody — edit the landing page in welcome.tsx directly; and lacak.tsx **copies** welcome.tsx's guest navbar + AnimatedButton rather than importing them, so a landing-navbar change must be duplicated there.

**Shared props** (app/Http/Middleware/HandleInertiaRequests.php): `name`, `auth.user`, `recaptchaSiteKey`, `sidebarOpen`, plus the flash props `success` / `error` / `generatedCredentials`.

**Routing & Wayfinder.** Routes live in routes/web.php (read its comment blocks before touching it) and routes/settings.php. @laravel/vite-plugin-wayfinder generates typed TS helpers into resources/js/actions/ (controller actions) and resources/js/routes/ (named routes). **Those directories are generated and gitignored — never edit by hand;** import from `@/actions/...` or `@/routes/...`.

**Authentication via Fortify.** No hand-written login/register/password controllers — Fortify provides them, configured in app/Providers/FortifyServiceProvider.php, with user-creation/password-reset logic in app/Actions/Fortify/ and shared rules as traits in app/Concerns/. **Admin login is Fortify itself, not a controller**: config/fortify.php sets `paths.login = 'admin/login'`, and FortifyServiceProvider wires `Fortify::loginView(auth/admin-login)` + `Fortify::authenticateUsing(...)` to match `username` + password and restrict to admin roles. Separate from the mahasiswa OTP flow (Auth\OtpLoginController, OtpToken, FormRateLimit) — the project's own addition, where `User.password` stores the active OTP hash rather than a chosen password. Role gating uses the `role:` alias → app/Http/Middleware/EnsureUserRole.php (registered in bootstrap/app.php), e.g. `role:admin_opd` or `role:admin_opd,admin_verifikator`, matching `UserRole->value` (403 on mismatch).

**Anti-abuse layer.** Both login paths apply the `InvalidatesOtherSessions` trait (app/Concerns/) — mahasiswa via Auth\OtpLoginController, admins via FortifyServiceProvider — clearing every other session for that user (database session driver) on top of the per-controller 403 guard. reCAPTCHA v3 guards the public form, OTP send, and admin login (frontend hook resources/js/hooks/use-recaptcha-v3.ts). Submission spam is throttled by RateLimitService/FormRateLimit.

**Global middleware (bootstrap/app.php)** — three things apply to every request, not per route: `SanitizeInput` (global stack, so it runs *before* FormRequest validation), `EnsureMustChangePassword` (appended to `web` after HandleInertiaRequests, plus aliased `password.changed`), and `trustProxies(at: '*')` so ngrok/reverse-proxy `X-Forwarded-*` headers are honoured and assets/redirects don't downgrade to `http://`. Cookies `appearance` and `sidebar_state` are excluded from encryption.

**Domain service layer.** Business logic lives in app/Services/, not controllers. The state machine is **SubmissionService** (submit, forwardToOpd, approve, reject, startOngoing, complete, resubmit): each transition runs in a `DB::transaction`, calls `guardStatus()` to reject out-of-order moves (`DomainException`), writes an ApplicationStatusLog audit row, mutates side state (approve increments the OPD's `quota_used`), and dispatches a job — match that shape for new transitions. Others: CertificateService (upload to the **private** disk; certificates start `is_download_locked = true`), LetterDocumentService, SkNumberService, AdminAccountService (`Str::password(12)` + `must_change_password`), OtpService, OtpLockoutService, ImageService (normalizes the pas foto via Intervention Image — scaleDown 1000px + JPEG q80, falling back to the original when GD/Imagick is missing so registration never fails), RateLimitService. Two services are bound by contract in app/Providers/AppServiceProvider.php (OtpServiceContract → OtpService, PengajuanServiceContract → SubmissionService) — type-hint the contract, not the class.

**Async side effects: Jobs + Mail + PDF.** Services dispatch queued app/Jobs/* (all on the `emails` queue, `tries = 3` with backoff) for every user-facing notice: confirmation, rejection, signed acceptance letter, certificate, OTP. Three job class names put "Job" in the middle — `GenerateJobAcceptanceLetter`, `SendJobCertificateNotification`, `SendJobRejectionEmail` — so grep for the concept, not the `…Job` suffix (and the test covering the first is named GenerateSuratPenerimaanJobTest). Each sends an app/Mail/* mailable rendered from resources/views/mail/*.blade.php. PDFs use DomPDF, are written to the private disk, and their paths are recorded on the model.

**Private-disk file surfaces.** All uploads live on the **private** `local` disk and are served through auth-guarded controllers, never a direct URL — follow this for any new upload. On internship_applications: `photo_path` (pas foto → GET pengajuan/{application}/foto, ApplicationPhotoController) and the optional `surat_pengantar_path` / `cv_path` / `portfolio_path` (from the welcome form, served inline via GET pengajuan/{application}/dokumen/{surat-pengantar|cv|portofolio}, ApplicationDocumentController; caps 2MB / 2MB / 10MB — keep the frontend "maksimal 2MB/10MB" copy in sync with StoreApplicationRequest). Authorization is InternshipApplicationPolicy::view (mahasiswa: own; Verifikator: all; OPD: only applications forwarded to it). Users carry `avatar_path`, auto-populated for mahasiswa from the registration pas foto and served by GET profile/avatar (ProfileAvatarController — parameter-less, always the authed user, so it can't leak someone else's photo). Certificates and presensi attachments use the same disk.

**Ticket numbers.** Canonical format `MGG-YYYY-NNNNNN` (e.g. `MGG-2026-000042`), from SubmissionService::generateTicketNumber (`sprintf('MGG-%d-%06d', ...)`). The public lacak page and every role page display/validate this — keep frontend masks/regex in sync. The retired `EMG-` prefix should be treated as suspect wherever it survives.

## Tests
Pest v4, on PostgreSQL (`magang_test`). Service unit tests are in tests/Unit/ (SubmissionServiceTest, CertificateServiceTest, OtpServiceTest, OtpLockoutServiceTest, RateLimitServiceTest). Feature tests have a **doubly-nested** layout: put new controller/flow coverage under tests/Feature/Feature/{Auth,Mahasiswa,Opd,Verifikator,Penyelesaian,Security}/. tests/Feature/Feature/Penyelesaian/EndToEndFlowTest.php walks the full lifecycle and is the best reference for wiring a new transition; Security/{SingleSessionTest,RecaptchaRateLimitTest,SanitizeInputTest} cover the anti-abuse guards.

**`Mail::fake()` cannot prove an attachment exists** — it never builds the Symfony message, so a mailable that lost its `attachments()` still passes. Anything asserting *about a PDF being attached* must go through the `array` transport and inspect the real message (count, filename, media type, body starting with `%PDF`); tests/Feature/GenerateSuratPenerimaanJobTest.php is the pattern. Related: the `local` disk has `'throw' => false`, so a failed `Storage::put()` returns `false` instead of raising — jobs that write a PDF check `$stored === false || ! exists()` and throw a named `RuntimeException` before mailing rather than recording a path for a file that isn't there.

Gotchas: local PHP may lack GD, so tests needing an uploaded image use `UploadedFile::fake()->create(..., 'image/jpeg')` rather than `->image()` — follow that. phpunit.xml sets `APP_URL=http://localhost` (a scheme-less dev `.env` otherwise mangles test URLs into host/host/path) and tests/TestCase.php calls `withoutVite()`, so the suite never needs a build.

**Baseline measured on branch `newback`, 2026-08-06: 231 tests — 221 passed, 10 skipped, 0 failing (1196 assertions), ~10s.** Green.

**Watch out for merges dropping test helpers.** Getting here required repairing two fixtures that a bad merge resolution (`39bd383`) had mangled: `tests/Feature/Feature/Verifikator/SkNumberTest.php` kept its `skSigner()`/`skOpdSiapAcc()` **call sites** while losing the **definitions** (fatal "undefined function", so the whole file died before asserting anything), and `tteOpd()` in Opd/TteFlowTest.php lost its explicit `'quota_used' => 0` — without which the "kuota tidak berubah" assertion compares an in-memory `null` against a refreshed `0` and fails even though the behaviour is right. Both helpers exist so that approve fixtures satisfy the TTE gate (signer + full letterhead); if an approve test starts failing with a null `sk_number`, **fix the fixture, never loosen `ApproveApplicationRequest`**.

The 10 skips are not a regression. Nine come from Fortify features this app deliberately leaves off (registration, password reset, two-factor) and bail out through `TestCase::skipUnlessFortifyHas()`; one is an explicit `->skip()` in Mahasiswa/ApplicationControllerTest for a page that was never built (the live form is welcome.tsx `#daftar`). A run reporting 0 skips means the suite changed, not that something got fixed — note that resources/js/pages/plan_revisi_akhir.md claims a 0-skip run, and that claim is **wrong**: the 2026-08-06 measurement above still skips 10.
